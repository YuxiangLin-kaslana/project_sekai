# Project Sekai

AI 操控的六边形文明世界模拟器。设计文档：`企划书.md`、`架构设计.md`（在线版为准）。

## 当前进度

P0：六边形地图 + 世界生成（地球规格 400×230、精细地球 800×460、陆地比例可调、地区 / 海区划分）+ 规则集加载 + 网页地图浏览器（分块加载、按缩放层级显示、可缩放侧边栏）。
对局核心已起步：国家 / 城市 / 单位 / 建筑的状态模型，开局摆放，指令校验，回合结算（移动与堆叠、建城、国家直接组织辖区施工、城市产出与生产队列、增长、维护费），网页上的领土、城市名牌和单位牌（兵牌）。已接入战术指挥：军事单位和城市的攻击范围、移动范围与路线预览，近战 / 远程 / 航空攻击、反击、城市占领、受击 / 损失 / 晋升动画；军事单位经验、城市 / 设施 / 大区发展等级；同格编成军团、整体移动、解散，抱团不能攻击。道路独立于地块景观，支持跨大区、河桥、浅水桥、山体隧道和沼泽堤道，并影响移动范围。城市管理规则 AI 已接入：按国家方针统一安排城市生产、开发和道路；默认关闭，可在对局面板开启。网页保留手动战术指挥，下一回合恢复移动力并推进经济；API 的 autoplay 可保留随机游走。陆地大区面积目标为 180 格（原 900 格的五分之一）。国家扩张与军事规则 AI 已接入，科技、外交和视野迷雾尚未实现。线上：https://sekai.yuxianglin.xyz

## 城市数量、资源与自动模拟

完整规则见 [游戏规则.md](游戏规则.md)。承载值是区域内的城市数量硬上限，所有国家共享名额；不限制单城人口和辖区。富饶地区城市更密集，贫瘠地区更稀疏。地图越大，承载区、初始辖区和城市间距越大，城市数量保持相近量级。显示面板提供「城市承载」图层。

资源总格数严格降低到相同地形/种子旧分布的一半，煤铁提高占比，宝石/石油/橡胶降低，新增极稀有钨和稀土。匹配且运作中的开采设施提供战略资源。首都道路网络生产 +25%，对外道路贸易每国 +2 金/城/回合，最多三个国家。道路包括外国道路都提供半点移动费用，仍遵守敌军占位和攻城规则。

「对局 → 规则 AI 自动模拟」默认关闭。开启后，各国自行建设、开拓和作战；可暂停并保留进度、调整速度、手动推进、单独接管城市或单位。每回合按固定次数轮转分配 AI 计算预算，部队共享寻路目标和通行费用；不接外交或模型调用。暂停推进保留国家 AI，「全部国家暂停 AI」关闭国家管理与单位决策。

当前测试：135 项后端测试。四国 200 回合新建 21 城、交战 767 次、占领 2 城，无非法指令及城市名额超限，冷热缓存结果一致。

验收记录：`out/ui-review/rule-ai-validation.json`、`rule-ai-browser.json`、`rule-ai-desktop.png`、`rule-ai-mobile.png`、`city-capacity-overlay.png`。复现四国 200 回合：`.venv/bin/python -m tools.rule_ai_review --turns 200`。

## 国家城市管理

在「对局 → 国家城市管理」选国家与方针，点击「开启本国托管」或「全部开启」，再推进回合。支持均衡发展、重视粮食、工业发展、积累国库、备战。默认不托管；城市没有独立控制者，管理器是国家的执行器。开启城市管理不会让军队随机移动。

粮食和生产按本城结算，金钱、科研和维护费全国汇总。托管城市先安排口粮，再按国家方针分配设施人口；根据缺粮、收入、维护费、在建项目和近城外国部队决定生产。队列里的单位也计入军备与未来维护费，避免多个城市重复使用同一份预算。人口即将增长时可提前开发地块；没有新增收益或实际防务需求时不建空闲设施，不为经济收益铺军事基地。

国家直接组织城外施工，不需要平民单位，每城同时一项城外工程，可与市中心生产并行。沿用设施的施工回合数、地形、资源、临水和人口运作规则；现有城外设施规则不收生产力或额外建造金费，建成后按规则收维护费。可在城市卡片选择辖区地块与设施手动开工，地图显示工地与剩余回合。工程失去城市或地块控制时终止并报告原因。

道路优先连接邻近本国城市和运作中的设施，复用现有道路，按既有工程价格从国库扣款，自动处理桥梁、隧道与堤道。每国每回合最多提交一条路线，保留至少 20 金、六回合当前亏空或每城 4 金的流动资金（取最大值）。预算不足则保留路线等待积累；无法施工的路线暂避五回合后再尝试。

手动安排生产或开发会接管该城，自动管理不改动其队列；「交回国家管理」保留已投入的生产和既有施工。国家关闭托管后不创建新计划，已安排的生产、工程继续完成。生产和施工原因跨回合保留，事件记录开始、完成、受阻、失败；国家面板显示收支、国库保留与军备目标，城市卡片显示粮食结余、决策原因和警报。

接口新增 `set_policy`、`city_management`、`develop_city` 三种国家指令；`GET /api/games/{id}/city-options?city=city:10` 只查询该城的合法开发选项，避免密集对局快照包含所有地块菜单。即时操作不会触发自动安排或推进施工；管理在回合的战斗后、经济结算前运行，所有自动命令仍经同一套引擎校验。

上一版城市管理验收（本版资源与城市规则已调整，以下为历史数据）：116 项后端测试通过；网页的单国 / 全部开关、方针、手动队列优先、恢复托管、直接施工与完成、手机布局通过。80×50、种子 42、四国分别使用均衡 / 粮食 / 工业 / 备战运行 100 回合：完成 17 项市中心建筑、65 项城外设施、12 支军事单位和 66 次道路工程（共 96 段道路）；无饥荒、无非法指令、无新增平民单位。回合中位数 38.38 ms、P95 78.76 ms，只计引擎结算，不含快照或网络；这是普通四城场景，不代表数千城市托管的性能。结果见 `out/ui-review/city-management-validation.json`，桌面与手机截图、浏览器验收在同目录。另在 115 城、192 单位的 80×50 密集场景完成一次烟测，关闭 / 开启托管的单回合结算为 94.33 / 309.17 ms，无非法指令；记录见 `out/ui-review/city-management-dense-smoke.json`。复现：

```bash
uv run python -m tools.city_management_review --seed 42 --turns 100
```

## 快速开始

地形生成面板提供「全陆地随机生成」开关，默认关闭。开启时用同一地图生成确定性的密集测试对局：所有陆地归属国家与城市，可建造陆地铺满城市或合法设施，仅生成军事单位，道路网络包含河桥、浅水桥、隧道与堤道。山地保留地形，火山不铺路；孤立单格陆地没有可连接的道路边。关闭开关恢复原普通对局，刷新页面默认回到关闭状态。

对局面板显示覆盖率、实体数量、生成 / 快照 / 获取解析耗时及数据量。「测量运行负载」在副本上结算一次真实回合，并在四个缩放下采样 Canvas 绘制耗时（中位数与 P95），完成后恢复镜头。测量不会改变当前回合。绘制耗时不是屏幕 FPS；浏览器、显卡、屏幕尺寸和网络会影响结果。服务仅保留最近两场密集测试对局，避免连续生成占用过多内存。

2026-10-09 实测（2 vCPU、7.6 GB 内存，Headless Chromium 软件绘制，1440×960 / DPR 1）：

| 地图 | 城市 | 军事单位 | 设施 | 道路段 | 副本结算 | 战术 / 建筑近景绘制中位数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 80×50 | 115 | 192 | 1,328 | 2,140 | 0.22 s | 11.8 / 4.8 ms |
| 400×230 | 1,990 | 4,933 | 31,207 | 43,545 | 2.64 s | 14.9 / 5.7 ms |
| 800×460 | 7,497 | 19,391 | 125,127 | 173,862 | 13.36 s | 15.9 / 5.7 ms |

最大密集场景的区域视角仍较重（中位数 340.6 ms）；世界全景为 12.9 ms。结算时间不包含整理快照与传输，服务进程峰值内存约 864 MB，包含缓存世界和保留的对局。上述为旧版负载，当前规则负载见 `out/ui-review/rule-ai-load.json`；旧版完整数据与 P95 见 `out/ui-review/stress-performance.json`，效果截图在同目录。范围 / 战斗 / 军团 / 道路 / 手机布局和默认关闭开关的浏览器验证通过；后端共 94 项测试通过。

需要 [uv](https://docs.astral.sh/uv/)（会自动装 Python 3.12）。

```bash

uv run python -m tools.mapgen --seed 3 --width 40 --height 25 --nations 4
uv run pytest -q                          # 测试
uv run ruff check . && uv run ruff format --check .
```

## Windows 下载包

`uv run python tools/windows/build.py` 在 Linux 上就能打 Windows 包（不需要 Windows 机器），输出到 `downloads/windows/`，
服务器在 `/downloads/windows/` 提供下载页、完整包、更新包和更新清单 `latest.json`：

- 完整包 `Sekai-<版本>-win64.zip`：Windows 嵌入式 Python 3.14 + 依赖 + 游戏代码，解压后双击“启动游戏.cmd”，
  在本机启动游戏服务器并用浏览器打开，不联网也能玩。
- 自动更新：启动器每次启动读 `latest.json`；运行环境（Python 和依赖版本）没变时只下载游戏代码包
  `sekai-app-<版本>.zip`，校验 SHA-256 后替换 `app/`；变了就打开下载页让玩家下新的完整包。
  游戏开着时每两小时再查一次，网页底部提示“重启即可更新”。
- 版本号按日期自动递增（`2026.10.10.1`、`.2`……）；发版就是重新跑一次打包脚本。

## 性能与多核

- AI 的共享距离场、长距离 A* 寻路是 Numba 内核（`engine/hexmap/kernels.py`），和原来的 Python 实现逐步一致、
  结果完全相同，运行时释放 GIL；同一回合要用的距离场一次批量算（`flow_fields`，多核并行）。
- 网格距离、范围查询有快速路径和缓存。同一局在 1 核、2 核上跑出的每回合状态哈希完全相同。
- 依赖都支持无 GIL 的 Python 3.14t（测试全部通过）；但目前一回合的大部分时间还在 Python 写的 AI 逻辑里，
  两局并发还没有明显提速，下一步要把各国的规划拆成可以并行的部分。
